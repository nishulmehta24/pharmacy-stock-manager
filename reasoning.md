# Reasoning & Thought Process

## Problem Understanding

The pharmacy problem has four core requirements:
1. **Batch tracking** — each medicine can have multiple batches with different expiry dates.
2. **FEFO dispensing** — always use the batch expiring soonest first.
3. **In-date stock count** — never count expired batches toward available stock.
4. **Expiry alerts + search** — heads-up on batches about to expire, and a quick "do we have X?" lookup.

---

## Architectural Decisions

### Why a Web App?
Chosen over CLI because pharmacy staff need a visual, easy-to-use interface without memorising commands. A web app also allows future multi-device access.

### Why Node.js + Express?
JavaScript throughout (frontend + backend) means no context switching between languages, making the codebase easier to understand and maintain.

### Why SQLite + Prisma?
- **SQLite**: A single-file local database — perfect for a single pharmacy location. No server to install or maintain.
- **Prisma**: Type-safe ORM with excellent developer experience. Auto-generates the database from the schema. Prisma v7 was used (latest), which required moving the datasource URL from `schema.prisma` into `prisma7.config.ts`.

### Why React + Vite + Tailwind?
- **React**: Component-based UI, industry standard, fast to build reusable parts (Card, Badge, Btn etc.)
- **Vite**: Instant dev server, much faster than Create React App.
- **Tailwind CSS**: Utility-first — the entire UI was styled inline without writing a single separate CSS file, which is faster for rapid development.

---

## Database Schema Design

Two tables were chosen deliberately:
- **Medicine** — stores the name and description. Has a `@unique` constraint on `name` to prevent duplicate entries.
- **Batch** — stores the quantity and expiry date per batch, linked to Medicine by foreign key.

This separation is the key to FEFO: instead of one field for "stock quantity", we have many rows per medicine, each with its own date.

---

## Core FEFO Logic

The dispensing algorithm (in `backend/src/index.js`, `POST /api/dispense`):

1. Query all `Batch` records for the medicine where:
   - `expiryDate >= today` (never dispense expired)
   - `quantity > 0` (skip empty batches)
2. Sort by `expiryDate ASC` (soonest to expire first).
3. Loop through sorted batches, deducting the requested quantity sequentially.
4. All database updates run inside a `prisma.$transaction([...])` — so if anything fails, nothing is committed (atomic operation).

## Issues Encountered and Fixed

### Issue 1: Prisma v7 Schema Error
**Problem:** `npx prisma db push` failed with error:
> "The datasource property `url` is no longer supported in schema files."

**Root Cause:** Prisma v7 (installed automatically as the latest version) changed the configuration format. The `url` field must now live in `prisma7.config.ts`, not `schema.prisma`.

**Fix:** Removed `url = env("DATABASE_URL")` from `schema.prisma`. The `prisma7.config.ts` (auto-generated by `prisma init`) already had the correct `datasource.url` field pointing to `process.env["DATABASE_URL"]`.

### Issue 2: `@prisma/client` Not Found
**Problem:** `npx prisma generate` failed with:
> "Could not resolve @prisma/client."

**Root Cause:** Prisma v7 separates the CLI (`prisma`) from the client (`@prisma/client`), and the client must be installed explicitly.

**Fix:** Ran `npm install @prisma/client` before regenerating.

### Issue 3: Interactive CLI Stalling
**Problem:** `npm create vite@latest` hung for 3+ minutes waiting for keyboard input on the linter selection prompt, blocking all progress.

**Fix:** Killed the stuck process and re-ran the command with the `--no-interactive` flag, which skips all prompts and uses defaults.

## Testing Approach

### Manual Testing Checklist
1. **Add medicine** → appears in dashboard stock list.
2. **Add two batches** with different expiry dates.
3. **Dispense** an amount > first batch quantity → verify first batch depleted to 0 and second batch reduced.
4. **Add an expired batch via API** → verify the dispensing endpoint rejects it.
5. **Search "paracetamol"** → verify "In Stock: Yes/No" reflects in-date stock only.
6. **Expiry alert** → add a batch expiring within 7 days, verify it appears in the amber alerts panel on the dashboard.
